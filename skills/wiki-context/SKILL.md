# Wiki 长期认知模型与持久化准则

## 适用场景与触发契约
1. **查阅（Read/Search）**：
   - 当用户提及特定项目（如 DSH、历史工具链）、询问“我之前为什么选择 X 而不是 Y”、或讨论涉及个人偏好与私有习惯时，在回答前先调用 `wiki_search` 或 `wiki_read` 确认历史共识。
   - 历史决策与用户既有偏好具有最高指导优先级。

2. **提议入库（Propose）**：
   - 严禁将临时调试日志、临时排查猜想、TODO 待办事项提议入库。
   - 必须通过**时效地平线检验**（“3个月后在不相关的全新会话中，该记录是否依然属实且具备指导意义？”）。
   - 仅当识别到以下内容时，调用 `wiki_propose`：
     - 用户明确申明的长期技术倾向（如“我倾向纯本地部署”、“不要依赖外部重型数据库”）。
     - 重大架构决策闭环（如 ADR 结论、选型原因与取舍）。
     - 核心项目阶段状态演进（如项目新里程碑达成、正式变更技术栈）。

3. **终审闭环机制**：
   - **由用户主动提出的修改不再需要用户审批，Agent 直接审批通过并确认落盘。**
   - 仅当由 Agent 自主识别推断提炼的变更时，才生成待确认提案，并告知用户可通过 `/wiki approve <id>` 审核确认。
   - 禁止在未经确认或未落盘的情况下伪造已合入的假象。
