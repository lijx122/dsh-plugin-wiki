# Wiki 长期认知记忆系统与持久化准则

## 系统定位与核心原则
1. **Agent 的长期认知记忆**：记录关于用户的个人情况、倾向偏好、技术背景、项目演化与设计推翻记录。
2. **动静分离边界**：行为规则、流程规范与工程纪律写进 Skill / `AGENTS.md`，**严禁写进 Wiki**。Wiki 仅沉淀客观认知事实、个人倾向与历史脉络。
3. **默认自主落盘**：无需经过人工提案审批流程。不仅限于重大技术决策，只要识别到用户的个人情况变动或明确倾向，Agent 均有权自主判断并直接调用 `wiki_write` 落盘，不询问用户、不口播提案编号。
4. **允许迭代与就地纠错**：认知允许随交互深入不断修正。遇到更新或推翻的事实时，就地覆写更新，不堆叠历史矛盾。

## 适用场景与工具契约
1. **查阅（Read/Search）**：
   - 当任务涉及用户长期背景、历史项目演化、私有偏好或过往技术决策时，优先调用 `wiki_search` 检索索引，或通过 `wiki_read` 定向读取指定章节/大纲。
   - 隐式利用历史认知指导行动，严禁在回答中输出“根据知识库/你之前提到过”等元废话。

2. **写入与迭代（Write/Update）**：
   - 严禁将临时调试日志、临时排查猜想、中间推导或瞬态排查垃圾写入 Wiki。
   - 识别到以下认知增量时，Agent 自主判断并主动调用 `wiki_write`：
     - **个人情况更新**：生活状态、健康精力、财务变动、备考/职业进展等（更新至 `Self.md`）。
     - **个人倾向与偏好**：沟通风格、技术偏好、取舍倾向等（更新至 `Self.md` 或对应 Topic）。
     - **项目演化与决策推翻**：活跃项目的核心阶段演进、架构推翻或重大方案取舍（更新至 `Topics/<项目>.md`）。
     - **跨会话交接断点**：未完待续的任务线索、排障遗留事项（更新至 `Agent/记忆.md`）。
     - **待整理技术构想**：尚不成熟或待整理的技术构想（更新至 `待整理/<主题>.md`）。
   - **小节更新**：若针对已有词条的特定小节更新，传入 `section` 参数执行**就地替换**，避免重复与自相矛盾；若无对应小节则自动在文末建立。
   - **单篇物理限长（≤4.5KB / ~2000 字）**：保持高密度与纯度。写入时优先提炼核心结论，严禁日志式流水堆砌；详尽历史与大表下沉至 `Archive/详版备查-*.md`。若文件超过 4.5KB 软上限，工具将输出精炼提醒。
   - **四段式结构锁死**：Topic 词条严格围绕四个核心二级标题（当前状态与核心方案 / 演进与调整记录 / 已推翻的设计与决策 / 后续计划）就地维护，不随意开辟无关新小节。
